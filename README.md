# Gantt

单人使用的本地甘特图桌面应用。数据存在你自己电脑上的 SQLite，不联网、不上云。

设计决策与取舍全部记录在 [`DESIGN.md`](./DESIGN.md)。

---

## 启动

### 环境要求

| | 版本 | 检查命令 |
|---|---|---|
| Node | ≥ 20 | `node -v` |
| Rust | ≥ 1.80 | `rustc --version` |
| Xcode Command Line Tools（macOS） | — | `xcode-select -p` |
| Microsoft C++ 生成工具（Windows） | VS 2019+ | 见下方「Windows」 |
| WebView2 运行时（Windows） | — | Win10 / Win11 自带 |

三样都有的话，直接：

```bash
npm install          # 首次
npm run tauri dev    # 启动
```

首次启动 Rust 要编译约 350 个 crate，**大概 1–3 分钟**；之后增量编译几秒钟。
窗口自动弹出，前端改动热更新，Rust 改动自动重启。

### Windows

在 Windows 上 `git clone` 下来，比 macOS 多准备一样东西：

1. 装 [Visual Studio 生成工具](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，
   勾选 **「使用 C++ 的桌面开发」**。SQLite 是随应用一起从 C 源码编译的（`rusqlite` 的
   `bundled`），没有 MSVC 编译器这一步会直接失败。
2. 装 Rust 时选默认的 `x86_64-pc-windows-msvc` 工具链（[rustup.rs](https://rustup.rs)）。
3. 然后和 macOS 一样：`npm install`、`npm run tauri dev`。

和 macOS 的差别都已经处理掉了，这里记一下免得以后改回去：

- 快捷键 `⌘` → `Ctrl`、`⌥` → `Alt`，界面上的提示也会显示成 `Ctrl+]`、`Alt+↑`
- 「在访达中显示」→「在资源管理器中显示」
- 看板拖卡片用的是指针事件而不是 HTML5 拖拽 —— Windows 上后者会被 Tauri 的
  文件拖放接管而整个失效（DESIGN.md §10）
- 发布版里屏蔽了 `F5` / `Ctrl+R`：WebView2 会把它当成「刷新网页」，撤销栈和
  还没落库的编辑会一起丢掉
- 仓库带了 `.gitattributes`，Windows 上检出也是 LF，两台电脑来回改不会出现整文件的换行符 diff

### 打包成独立应用

```bash
npm run tauri build
```

产物在 `src-tauri/target/release/bundle/`：

- macOS：`dmg/Gantt_0.1.0_aarch64.dmg` 和 `macos/Gantt.app`
- Windows：`msi/Gantt_0.1.0_x64_zh-CN.msi` 和 `nsis/Gantt_0.1.0_x64-setup.exe`（安装界面是中文）

> **不能交叉编译。** macOS 上打不出 Windows 包，反之亦然。
> 仓库里的 `.github/workflows/build.yml` 会在 GitHub Actions 的 Windows 机器上
> 跑全部测试并打包，安装包在该次运行的 Artifacts 里下载。
>
> 个别精简过的 Windows 11 删掉了 VBScript，打 msi 的 WiX 会因此失败 ——
> 那就只打 exe：`npm run tauri build -- --bundles nsis`。

## 换台电脑接着干

项目可以整个导出成一个 `.ganttproj` 文件，拷到另一台电脑再导回来。
数据是全的 —— 任务、层级、依赖、实施日期、受阻时段、风险、评论、逐日记录、
基线、负责人和头像，一样不少。

> 这和工具条上的 **导出 Excel / 导出时间线** 不是一回事。
> 那两个是**给人看**的排版件，发给老板和甲方用，导不回来；
> `.ganttproj` 是**给这个软件看**的数据，只用来在两台机器之间搬项目。

### 导出

项目列表页 → 悬停卡片 → **⤴ 导出**。
对话框会记住你上次选的目录（比如云盘里那个），下次直接开在那儿、文件名也填好了。

### 导入

项目列表页右上角 **↧ 导入项目**，或者直接把 `.ganttproj` **拖进窗口**。

导入前会先弹一个预检：文件里有多少任务、多少风险、时间跨度多少。
如果本机已经有这个项目，会把两边的数字并排摆出来，让你自己判断该不该覆盖。

### 来回传的时候它怎么认出是同一个项目

每个项目有一个跟着它走的 `uuid`，无论传几台电脑都不变。所以：

- **uuid 对上** → 同一个项目，哪怕你在另一台电脑上把它改了名（覆盖时顺便改回来）
- **uuid 没对上、名字对上** → 也算同一个（第一次用这个功能时靠这条）
- **都没对上** → 全新项目

项目名在库里是唯一的，这是"名字兜底"能成立的前提。新建时敲到重名会当场提示。

### 出错和后悔

- **导入是全有或全无。** 文件里只要有一条数据不合法，整个导入就被拒绝，
  并且用人话告诉你是哪几条 —— 数据库一个字都不会被改。
- **覆盖前自动备份。** 本机那一版会先整份导成 `.ganttproj` 存进 `backups/`，
  导完列表页顶上有个**撤销**按钮。横幅关掉之后文件还在，随时能手动导回来。
- **版本不一样也能传。** 两台电脑的 Gantt 版本不同时：只是新增字段的（次版本号变），
  旧版照常导入并提示忽略了什么；语义变了的（主版本号变），旧版会明确拒绝而不是
  半懂不懂地导进来。

### 文件里面是什么

`.ganttproj` 就是个 zip，改名成 `.zip` 能直接解开：

```
manifest.json     格式版本、导出时间、项目名和 uuid
project.json      项目 + 任务 + 依赖 + 风险 + 评论 + 逐日记录 + 基线
people.json       只含这个项目用到的负责人
avatars/1.png     头像还原成真实图片，不是 base64 字符串
```

JSON 是缩进过的，能读、能 diff、必要时能手改 —— 一个自己都打不开的备份格式，
出事的时候给不了任何安全感。

### 整个库一起搬（`.db`，比如从 Mac 搬到 Windows）

项目多的时候一个个导 `.ganttproj` 太累，可以直接搬整个数据库：

1. 旧电脑：**设置 → 数据 → 导出数据库…**，得到一个 `Gantt-数据库-日期.db`
2. 拷到新电脑，项目列表页 **↧ 导入项目** 选中它（或者直接拖进窗口）
3. 预检里逐个列出每个项目是**新建**还是**覆盖本机某个项目**，确认后一次导入

SQLite 文件本身不分 Mac 和 Windows，所以这几种 `.db` 都能导：

- 「导出数据库」导出的文件（推荐：单文件，自给自足）
- 旧电脑 `backups/` 里的自动备份 `gantt-日期.db`
- 旧电脑数据目录里的 `gantt.db` 本身 —— 但要么先退出那边的 Gantt，要么把同目录的
  `gantt.db-wal` 一起拷过来，否则最近一段修改还在 `-wal` 里没带上（预检会提醒）
- 旧版本 Gantt 的库也行，会在临时副本上先升级，源文件一个字节不动

规则和 `.ganttproj` 完全一样（它们走的是同一条写库路径）：uuid 优先、名字兜底；
**本机独有的项目不受影响**；同名负责人沿用本机的，没被任何任务用到的负责人也会一起带过来。
全部项目在一个事务里写，有一个不合格就一个都不写。导入前会把本机整库快照成
`backups/整库导入前-时间.db`，导完横幅上的**撤销**就是把它恢复回来。

## 操作

### 鼠标

| 操作 | 效果 |
|---|---|
| **⌘/⌃ + 滚轮**（或触控板捏合） | 连续缩放，**以鼠标位置为锚点** |
| 拖甘特条中间 | 整体平移（保持工期） |
| 拖甘特条左/右边缘 | 改工期（另一端不动） |
| 拖进度填充的右边界 | 调进度，吸附到 25/50/75/100 |
| 拖父任务条 | 整组平移全部子任务 |
| 拖空白处 | 水平平移时间轴 |
| **单击日期单元格** | 打开日历浮层选日期（也可直接键入） |
| 双击其他单元格 | 就地编辑 |
| 悬停任务名右侧的 **+** | 给这一行添加子任务 |
| 拖动网格与甘特图之间的分隔条 | 调整左侧面板宽度（双击复位，宽度会记住） |
| 工具条 **工作日历** | 配置每周工作日与节假日（按项目存） |
| 工具条 **着色** 下拉 | 甘特条按 阶段 / 负责人 / 紧急度 / 单色 上色 |
| 在甘特区移动鼠标 | 时间游标竖线 + 顶部日期，用来对齐远处的条子 |
| 悬停某根条子 | 所有**时间上与它重叠**的条子被描边（此刻还有谁在并行） |

### 键盘

| 键 | 效果 |
|---|---|
| `⌘Z` / `⇧⌘Z` | 撤销 / 重做 |
| `Enter` | 在选中行**紧后面**新建同级任务 |
| `⇧Enter` | 在选中行**下面**新建子任务 |
| `⌘]` / `⌘[` | 缩进 / 取消缩进（把已有任务变成子任务） |
| `⌫` | 删除选中任务及其全部子任务 |
| `1` `2` `3` `4` | 跳到日 / 周 / 月 / 年档位 |
| `T` | 回到今天 |
| `⌘S` | 立即落库（平时 400ms 自动保存） |

Windows 上 `⌘` 一律对应 `Ctrl`、`⌥` 对应 `Alt` —— 快捷键和界面上的提示文案都走了
平台抽象（`src/core/keys.ts`），没有硬编码。

## 代码结构

```
src/
  core/          纯逻辑，不依赖 React 和 Tauri，全部有测试
    edits.ts         编辑原语（行级前后快照）
    commandStack.ts  撤销/重做栈，支持复合命令与手势合并
    dateLink.ts      日期三值联动规则
    keys.ts          快捷键的平台抽象
  gantt/         甘特图引擎
    viewport.ts      单一状态量 pxPerDay 的相机
    scale.ts         刻度阶梯的连续演化（无模式判断）
    render.ts        三层 Canvas 绘制
    model.ts         层级展平与工期加权汇总
    hitTest.ts       甘特条命中检测
    coloring.ts      语义着色（色相由数据决定，不由行号决定）
  transfer/      项目文件（.ganttproj）在前端这侧的编排：挑路径、记住上次的目录
  db/            持久化
    api.ts           Rust 命令的类型化包装
    convert.ts       ISO 日期 ↔ 天序号
    persistence.ts   防抖落库调度
  screens/       界面
  store/         Zustand 状态

src-tauri/
  migrations/001_init.sql   schema（唯一知情方）
  src/db.rs                 类型化命令 + 事务写入
  src/transfer.rs           .ganttproj 的导出/导入：zip 容器、校验、身份匹配
  src/dbfile.rs             整库 .db 的导出/导入：副本上迁移、逐项目复用 transfer 的写库路径
  src/backup.rs             滚动备份、单文件快照
```

**一条纪律**：任务数据只能经由命令栈修改。
遵守它，撤销/重做/落库三件事自动全部正确；绕过它，三件事同时失效。
